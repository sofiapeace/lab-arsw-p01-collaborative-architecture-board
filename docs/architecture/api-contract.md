# REST Contract — Lab 04

| Method | Resource | Request | Success response | Error cases |
|---|---|---|---|---|
| POST | `/api/boards` | `{ "name": "string (required, non-blank)" }` | `201 Created` + Board body (`id` generated by the server, `elements` starts as `[]`) | `400` `INVALID_REQUEST` if `name` is blank/missing |
| GET | `/api/boards/{boardId}` | - | `200 OK` + Board body | `404` `BOARD_NOT_FOUND` if `boardId` does not exist |
| PUT | `/api/boards/{boardId}` | `{ "name": "string (required)", "elements": [BoardElement, ...] }` | `200 OK` + updated Board body (same `id` as before) | `404` `BOARD_NOT_FOUND` if `boardId` does not exist (does **not** create it); `400` `INVALID_REQUEST`/`INVALID_INPUT` on an invalid body |

`Board` body shape:
```json
{
  "id": "a35dfe85-5efc-44dd-a9c6-e3642a9d3e22",
  "name": "Mi tablero",
  "elements": [
    { "id": "e1", "type": "RECTANGLE", "x": 0, "y": 0, "width": 100, "height": 50, "text": "" }
  ]
}
```
`elements[].type` is one of `RECTANGLE`, `TEXT`.

## Error contract

```json
{
  "timestamp": "2026-09-05T00:57:18.181950600Z",
  "status": 404,
  "code": "BOARD_NOT_FOUND",
  "message": "Board not found: no-existe",
  "path": "/api/boards/no-existe"
}
```

`code` values in use: `BOARD_NOT_FOUND` (404), `INVALID_REQUEST` (400, bean-validation failure on the request body), `INVALID_INPUT` (400, a domain invariant rejected the input), `LAB_NOT_IMPLEMENTED` (501, safety net for an unimplemented use case — should not fire in this delivery).

## Deviations from the starter contract

None in shape. Two behaviors worth stating explicitly, since the table above doesn't capture edge cases:

- **`PUT` never creates a board implicitly.** Replacing a board that doesn't exist returns `404 BOARD_NOT_FOUND`; it is not an upsert. This is a deliberate decision, justified in `ADR-001-repository-boundary.md`.
- **The board `id` is always server-generated** (a UUID) on `POST`. The client has no way to choose or send one.
